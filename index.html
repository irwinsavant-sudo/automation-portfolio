Business Expense Tracking System

Client name withheld
  • Pulls business credit card transactions through Plaid, asks each cardholder in Slack to explain the charge, and writes every response to Google Sheets so the accountant stops chasing people by hand.
  • Runs as several linked n8n workflows on a self-hosted instance in Docker on Hugging Face Spaces, with persistent storage and scheduled backups to GitHub.
  • Includes a dashboard for the accountant with filters by card, editable transaction details, status tracking and receipt upload.
  • A Cloudflare Worker sits in front of the instance for rate limiting and CORS. Webhooks use header-based secrets and Slack signature checks, and inputs are sanitized against XSS.
  • I worked directly with the accountant, explained how the system works, and trained them to move it from test to production. I handed it over with no ongoing access for me, since it handles real company credit cards.

What broke and what I changed

  • SQLite would not persist on the host.The host filesystem does not support SQLite file locking. The database now downloads on boot and uploads on sync, with write-ahead-log checkpoints and checksums so unchanged files are not re-uploaded.
  • A column shift corrupted sheet data.Columns were read by position. They are now mapped by header name.
  • Transactions vanished between steps.A misconfigured Merge node dropped them without an error. Corrected the Merge configuration.
  • Plaid rejected requests.The proxy forwarded fields Plaid does not accept (UNKNOWN_FIELDS). The proxy now stops forwarding them.
  • The Worker pointed at old workflows.Its workflow map held stale IDs for all six workflows. Replaced them with the current IDs.

Personal project

AI Lead Management Pipeline

One workflow, many businesses
  1. Intake form
  2. n8n webhook
  3. Client settings from Notion
  4. LLM scores the lead
  5. Switch routes to 1 of 6 tracks
  6. Gmail sequence
  7. Notion pipeline log
  • Takes submissions from a multi-step HTML intake form I built, which posts to an n8n webhook with automatic retries.
  • Loads each client's settings from Notion (target customer profile, offer, email templates, booking link), so one workflow serves different businesses.
  • An LLM scores each lead on budget, timeline, role, and fit with the client's target customer, then assigns one of six tracks. A Switch node routes it.
  • Sends a track-specific Gmail sequence with timed waits, from a 2-day nudge up to a 90-day check-in, and notifies the business owner at each stage.
  • Logs every lead to a Notion pipeline database. It checks by email first, so repeat submissions update the existing record.
  • Missing form fields and malformed AI output fall back to safe defaults: the lead goes to Warm for manual review. Failures are written to a Notion error log.
